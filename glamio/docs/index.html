Welcome to Glamio

Glamio is a booking app for one salon or barbershop. Clients book on their phone, stylists see their day on their phone, and the owner runs everything from a website.

This guide assumes you have never built an app before. It explains every step in plain words, from installing the tools to publishing in the app stores. Words that may be new to you are explained in the Glossary.

📱

Phone app

For clients (book, change, cancel) and stylists (their schedule). Android and iPhone. Folder mobile/.

🖥️

Web admin

A website for the owner: calendar, services, stylists, hours, clients, settings. Folder admin/.

🗄️

Backend

The database and the booking rules, hosted on Supabase. Folder supabase/.

How long does this take? Installing the tools: about 1–2 hours the first time (mostly waiting for downloads). Setting up your salon (Steps 1–9): about 1 hour. Publishing in the stores takes longer, because Google and Apple review your app.
Watch first: the 4-minute setup video The Glamio setup video shows all 9 steps in order. Watch it once, then follow this guide; every command is here to copy.

How Glamio works

Think of a salon's paper appointment book. Glamio puts that book online, in one safe place (the database). The phone app and the web admin are two windows onto the same book: whatever one writes, the other sees at once.

  • Supabase is a service that keeps your database online. The booking rules live there too: for example, two clients can never book the same stylist at the same time, even if they press "Book" at the same second.
  • Resend sends the 6-digit sign-in codes by email. Nobody needs a password.
  • Firebase (optional) delivers push messages: "Booking confirmed", "See you tomorrow".
  • Vercel (or Netlify) puts the web admin on the internet, at an address like your-salon.vercel.app.

Who sees what

PersonUsesCan do
ClientPhone appBrowse services (no account needed), book one or more services, pick a stylist or "any", change or cancel before the cut-off time, see history, delete their account.
Stylist (staff)Phone appSee their own schedule live, add walk-in clients, mark bookings Completed or No-show.
OwnerWeb admin (and the phone app)Everything: services, stylists, working hours, time off, closures, calendar, phone and walk-in bookings, clients, settings, numbers.

The app decides who someone is by their email address. There are no passwords to forget.

The terminal, in 3 minutes

Some steps ask you to "run a command". A command is a line of text you type into the terminal, a window where you talk to your computer by typing instead of clicking. You only need a few commands, and you can copy each one from this guide with the Copy button.

Open a terminal

Press ⌘ + Space, type Terminal, press Enter.

Press the Windows key, type PowerShell, press Enter.

Easiest way: the terminal inside VS Code Once you have installed VS Code (next section) and opened the Glamio folder in it, choose Terminal → New Terminal from the menu. A terminal opens at the bottom, already in the right folder.

Three things to know

  1. Paste and press Enter. Copy a command from this guide, paste it into the terminal (⌘+V on Mac, right-click or Ctrl+V on Windows), then press Enter.
  2. Folders matter. A command works on the folder the terminal is "in". To move into a folder, type cd and the folder name. For example cd mobile moves into the phone app folder, and cd .. goes back up one level.
  3. Wait for the prompt. When a command is finished, the terminal shows a new empty line to type on. Some commands take minutes the first time; that is normal.
Example
cd mobile        # go into the phone app folder
cd ..            # go back to the main Glamio folder

Text after a # is a note for you. You can paste it along; the terminal ignores it.

Install the tools · 1 of 8

VS Code, the editor

VS Code is a free program for opening and editing code files, a bit like Word but for code. You will use it to change settings files and to run the app.

  1. Download it from code.visualstudio.com and install it like any program.
  2. Open VS Code. Click the Extensions icon on the left (four small squares), search for Flutter and click Install. This also installs the Dart extension.
  3. Unzip the Glamio download somewhere easy, for example Documents/glamio. In VS Code choose File → Open Folder… and pick the folder that contains mobile, admin and supabase.
Avoid spaces and special characters in the folder path Some tools break on paths like C:\My Files\Glamio (copy). Use something simple like C:\dev\glamio or ~/dev/glamio.

Git

Git keeps the history of your code and uploads it to GitHub. You need it in Step 6 to put the web admin online.

Run this in the terminal. A window asks to install the "command line developer tools"; click Install. (If Git is already there, it says so; that's fine.)

xcode-select --install

Download Git for Windows from git-scm.com and install it. The default options are fine: just keep clicking Next.

Then tell Git your name and email (used to label your changes):

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
Install the tools · 3 of 8

Flutter

Flutter is Google's toolkit for building apps. One code base makes both the Android and the iPhone app. The easiest way to install it is from inside VS Code:

  1. In VS Code press Ctrl+Shift+P (⌘+Shift+P on Mac). A search box opens at the top: the Command Palette.
  2. Type Flutter: New Project and press Enter.
  3. VS Code says it can't find the Flutter SDK. Click Download SDK.
  4. Choose a folder for Flutter, for example C:\dev (Windows) or your dev folder (Mac). Not Program Files.
  5. Wait for the download (several minutes). When VS Code asks Add SDK to PATH, click it. This lets the terminal find Flutter.
  6. Close the "new project" box that may appear (you don't need a new project), then close and reopen VS Code and any terminal.

Check that it worked. In a new terminal:

flutter --version

You should see something like Flutter 3.x.x • channel stable. Glamio is tested with the current stable Flutter.

Prefer the manual way? Flutter's official guide covers every system in detail: docs.flutter.dev/get-started/install.
Install the tools · 4 of 8

Android Studio

You won't write code in Android Studio, but Flutter needs its Android SDK (the Android building blocks) and its emulator (a pretend Android phone that runs on your computer).

  1. Download Android Studio from developer.android.com/studio and install it with the standard options. On first start it downloads the Android SDK; let it finish.
  2. On the welcome screen click More Actions → SDK Manager. Open the SDK Tools tab, tick Android SDK Command-line Tools, and click OK.
  3. Accept Google's licences. In a terminal run the command below and type y + Enter every time it asks. 
    flutter doctor --android-licenses
  4. Create an emulator: on the welcome screen click More Actions → Virtual Device Manager → + (Create device) → pick a phone such as Pixel 8 → Next → pick the newest system image (click the download icon next to it if needed) → Finish.
  5. Press the ▶ play button next to the new device. A phone appears on your screen. Leave it open when you run the app later.

Xcode (Mac only)

Xcode is Apple's tool for iPhone apps. Skip this section on Windows; you can still do everything for Android.

  1. Install Xcode from the Mac App Store (large download, about 10 GB). Open it once and let it install extra components.
  2. In the terminal, finish Xcode's setup: 
    sudo xcodebuild -runFirstLaunch
    It asks for your Mac password. While you type, nothing appears on screen; that's normal. Press Enter when done.
  3. Install Homebrew (an installer for developer tools) by following the one-line command on brew.sh. At the end it may print two or three commands under "Next steps"; run those too.
  4. Install CocoaPods (Flutter uses it to build iPhone apps): 
    brew install cocoapods
  5. For the iPhone simulator: open Xcode → Settings → Components (called Platforms in some versions) and download the newest iOS simulator.

Node.js

Node.js runs the web admin on your computer and installs its building blocks. You need version 20.9 or newer; the current LTS ("long-term support") version is the right choice.

  1. Download the LTS installer from nodejs.org and install it with the default options.
  2. Close and reopen your terminal, then check:

    You should see a version like v22.x.x or higher.
Install the tools · 7 of 8

Supabase CLI

The Supabase CLI is a small command-line tool that sends Glamio's database tables, settings and server functions to your Supabase project.

brew install supabase/tap/supabase
supabase --version

On Windows the simplest way is to run it through Node.js, with nothing extra to install. Wherever this guide says supabase, type npx supabase instead. The first time, it asks Ok to proceed? (y): type y and press Enter.

npx supabase --version

(Prefer a permanent install? See Supabase's CLI guide, "Windows" with Scoop.)

You do not need Docker Some Supabase guides mention Docker. That is only for running a database on your own computer. This guide uses Supabase's online service, so you can skip Docker.

Check everything

Flutter has a built-in health check. Run:

flutter doctor

It prints a list with ✓ (good) and ✗ or ! (needs attention). You need ✓ for:

  • Flutter
  • Android toolchain (if not: run flutter doctor --android-licenses again)
  • Xcode (Mac only, for iPhone)
  • VS Code

A ✗ for "Chrome", "Visual Studio" or "Linux toolchain" is fine: Glamio doesn't use them.

Two warnings you can ignore: on an Intel Mac Flutter shows a "!" saying it will need an Apple Silicon Mac in a future version (it still works today), and "Connected device" may complain about an iPhone on Wi-Fi. That only matters when you run on that iPhone (Step 8d).

Set up your salon · Step 1

Create the database (Supabase project)

  1. Sign in at supabase.com/dashboard and click New project.
  2. Fill in:
    • Name: your salon's name, for example Rosa Hair Studio.
    • Database password: click Generate a password and save it in your notes. You need it in Step 2.
    • Region: Auto is fine, or click Need a specific region? and pick the one closest to your salon (shorter distance means a faster app).
    • Security: leave Enable Data API and Automatically expose new tables ticked, as they are by default. Enable automatic RLS can stay as it is.
  3. Click Create new project and wait 1–2 minutes.
  4. Collect three things for your notes:
    • Project reference ("project ref"): Project Settings → General → Project ID. It looks like abcdefghijklmnopqrst.
    • Project URL: https:// + your project ref + .supabase.co.
    • Publishable key: Project Settings → API Keys. It starts with sb_publishable_. (Older projects call it the anon key; that one works too.)
Keep "Automatically expose new tables" ticked Supabase suggests unticking it, but Glamio's app and web admin need it: without it every screen fails with "permission denied". Your data stays protected, because Glamio switches on row-level security for every table and its tests check that no one can see another person's data.
Never share the "secret" or "service_role" key The same page also shows a secret key. Glamio never needs it in the app or the web admin. Anyone who has it can read and change everything in your database.
Set up your salon · Step 2

Fill the database with Glamio's tables

Now you send Glamio's tables and booking rules to your new project. Open a terminal in the main Glamio folder (the one that contains supabase).

  1. Sign in to Supabase from the terminal. A browser window opens; click Authorize. 
    supabase login
  2. Connect this folder to your project. Replace YOUR-PROJECT-REF with your project ref. When it asks for the database password, paste the one from Step 1 (nothing shows while you paste; press Enter). 
    supabase link --project-ref YOUR-PROJECT-REF
  3. Send the tables and rules. When it lists the files and asks to continue, type y and press Enter. 
    supabase db push

When it ends with Finished supabase db push., your database is ready. In the Supabase dashboard, Table Editor now lists tables such as bookings, services and staff.

Windows reminder Type npx supabase instead of supabase.
Set up your salon · Step 3

Sign-in emails (Resend)

To sign in, a person types their email and receives a 6-digit code. Supabase's built-in email sender is only for testing: it sends very few emails per hour, and it doesn't allow the code email Glamio needs. So you connect your own sender. We use Resend, which is free for small volumes.

3a. Set up Resend

  1. Sign up at resend.com.
  2. Go to Domains → Add Domain and enter your domain, for example yoursalon.com. For Region, pick the one closest to your clients (for example Ireland for Europe, or N. Virginia for the US).
  3. Resend shows a few DNS records (lines of settings). Log in where you bought your domain, open its DNS settings, and add each record exactly as shown. Then click Verify in Resend. It can take from a few minutes to a few hours before it turns green.
  4. Go to API Keys → Create API Key, give it a name, and copy the key (starts with re_) into your notes. It is shown only once.

3b. Connect Resend to Supabase

  1. In the Supabase dashboard open Authentication → Emails → SMTP Settings and switch on Enable custom SMTP.
  2. Fill in:
    Sender emailno-reply@yoursalon.com (your verified domain)
    Sender nameYour salon's name
    Hostsmtp.resend.com
    Port465
    Usernameresend
    PasswordYour Resend API key (re_…)
  3. Click Save.

3c. Send Glamio's sign-in settings

This sends the code email design and the sign-in settings (code length, expiry) to your project. In the terminal, in the main Glamio folder:

supabase config push

It lists the changes and asks to confirm; type y and press Enter.

Do 3b before 3c Supabase refuses custom email designs while its own built-in sender is in use. If config push complains about email templates, check that custom SMTP is switched on and saved.
Set up your salon · Step 4

Add your business

  1. In VS Code open supabase/setup.sql.
  2. Change the values in quotes:
    supabase/setup.sql
    insert into public.businesses (id, name, timezone, currency, phone, address)
values ('00000000-0000-0000-0000-00000000b001', 'Rosa Hair Studio', 'Europe/London', 'GBP', '+44 20 1234 5678', '1 High Street, London');

insert into public.invites (business_id, email, role)
values ('00000000-0000-0000-0000-00000000b001', 'owner@yoursalon.com', 'owner');
    • Time zone: the official name of your salon's time zone, such as Europe/London, America/New_York, Asia/Dubai, Asia/Karachi or Australia/Sydney. Full list: tz database time zones (column "TZ identifier"). It matters: all booking times are calculated in it, including daylight-saving changes.
    • Currency: a 3-letter code: USD, EUR, GBP, AED, PKR, …
    • Owner email: the email you will sign in to the web admin with. Use an inbox you can open right now.
    • Leave the long id (00000000-…-b001) as it is. The phone app uses the same id.
  3. In the Supabase dashboard open SQL Editor → New query. Copy the whole file into it and click Run. You should see Success. No rows returned.
Run it only once Running it a second time shows "duplicate key", which only means your business already exists. You can change the name, time zone and currency later in the web admin's Settings.
Set up your salon · Step 5

Upload the two server functions

Glamio has two small programs that run on Supabase's servers: delete-account (lets people delete their account, which Google and Apple require) and send-notifications (push messages). Upload both:

supabase functions deploy delete-account send-notifications --use-api

When it prints Deployed Functions, you'll see both under Edge Functions in the dashboard. (--use-api means "build them on Supabase's side", so nothing else is needed on your computer.)

Set up your salon · Step 6

Put the web admin online

The web admin must be on the internet so you can open it from any computer or phone. Vercel builds it from a private copy of your code on GitHub.

6a. Upload your code to a private GitHub repository

  1. On github.com/new create a repository: give it a name, choose Private, and leave all the "Add a README / .gitignore / license" boxes unticked. Click Create repository.
  2. In the terminal, in the main Glamio folder, run these lines one by one. In the 5th line, replace the address with the one GitHub shows you (it ends in .git). 
    git init
git add .
git commit -m "My Glamio salon"
git branch -M main
git remote add origin https://github.com/YOUR-NAME/YOUR-REPO.git
git push -u origin main
    If it asks you to sign in to GitHub, follow the browser window that opens.
Always private Your Glamio licence does not allow publishing the source code. Keep the repository Private. Your secret settings files (.env) are left out automatically.

6b. Deploy on Vercel

  1. Sign up at vercel.com with your GitHub account.
  2. Click Add New… → Project and Import your Glamio repository.
  3. Next to Root Directory click Edit and choose admin. Vercel then recognises it as a Next.js site.
  4. Open Environment Variables and add two:
    NameValue
    NEXT_PUBLIC_SUPABASE_URLYour Project URL (https://….supabase.co)
    NEXT_PUBLIC_SUPABASE_ANON_KEYYour publishable key (sb_publishable_…)
  5. Click Create Project. If Vercel offers Optional Integrations → Supabase → Add, skip it: that would make a new, empty database instead of using yours.
  6. Click Deploy and wait 2–3 minutes. You get an address like https://rosa-hair.vercel.app. Save it in your notes: this is your web admin address.

Deployment says "Blocked"? On Vercel's free Hobby plan, a private GitHub repository only deploys commits made by the same GitHub account you signed in to Vercel with. Make sure your Git name and email on your computer match that account (git config user.email), then push a new commit.

Using Netlify instead? Add new site → Import an existing project, set Base directory to admin and the build command to npm run build, and add the same two variables.

6c. Tell Supabase your web admin address

  1. Supabase dashboard → Authentication → URL Configuration: set Site URL to your web admin address and add the same address under Redirect URLs. Save.
  2. In VS Code open supabase/config.toml, find the line site_url = "http://localhost:3000" and put your web admin address there too. Then a later supabase config push won't change it back.

6d. Sign in as the owner

  1. Open your web admin address. Enter the owner email from Step 4 and click Send code.
  2. Check your inbox (and the spam folder) for "Your sign-in code". Type the 6 digits and click Sign in.
  3. You see the Dashboard with a "Finish setting up" list. 🎉
Set up your salon · Step 7

Fill in your salon in the web admin

The dashboard's "Finish setting up" list walks you through this. Clients can only book once there is at least one service and one stylist with working hours who does that service.

Settings

Your address, phone, about text and logo, plus the booking rules:

SettingWhat it meansExample
Start times everyThe gap between the times clients can choose15 min → 9:00, 9:15, 9:30…
Book up toHow far ahead clients can book30 days
Minimum noticeHow soon a booking can start, counted from now60 min: at 10:00 the first free time is 11:00
Clients can change or cancel untilAfter this, clients must call you2 h before
Upcoming bookings per clientStops one person from blocking many times5

Also on Settings: Closures, days the whole salon is closed (holidays). No one can book on those days.

Services

Add what you sell. For each service:

  • Duration: how long it takes, for example 30 minutes.
  • Extra time after: cleaning or drying time when the stylist is still busy but the client is gone. Clients don't see it; it only keeps the next booking from starting too early.
  • Price, an optional photo, a category (Hair, Beard, Colour…), and which stylists do it.
  • Active: switch it off to hide a service you no longer offer. It disappears for new bookings, but existing bookings keep it and can still be moved. Hiding is safer than deleting.

Stylists

Add each person who takes bookings: name, title, photo, short bio. Then, on their page:

  • Services: tick what they do.
  • Working hours: per weekday; several periods a day are fine (for example 9–13 and 14–18 for a lunch break).
  • Time off: holidays or appointments of this one person.
  • Portfolio: photos of their work, which clients see when choosing a stylist.
  • App access: see Staff app access.
Set up your salon · Step 8

Run the phone app

8a. Create the app's settings file

The app reads its settings from a file called .env in the mobile folder. You make it by copying the example file:

cd mobile
cp .env.example .env
cd mobile
copy .env.example .env

Open mobile/.env in VS Code and fill in the first lines:

mobile/.env
SUPABASE_URL=https://YOUR-PROJECT-REF.supabase.co
SUPABASE_ANON_KEY=sb_publishable_xxxxxxxxxxxxxxxx
BUSINESS_ID=00000000-0000-0000-0000-00000000b001

ADMIN_URL=https://rosa-hair.vercel.app     # your web admin address
GOOGLE_SIGN_IN=false
GOOGLE_WEB_CLIENT_ID=
GOOGLE_IOS_CLIENT_ID=
PUSH_ENABLED=false
DEMO_MODE=false

Leave the other switches on false for now. You can turn on push and Google sign-in later (see Push and Google sign-in).

No spaces, no quotes Write NAME=value exactly like that: no spaces around = and no quotation marks.

8b. Start a phone

  • Android emulator: start it from Android Studio's Device Manager (▶).
  • iPhone simulator (Mac): run open -a Simulator.
  • Your own Android phone: in Settings → About phone, tap Build number 7 times to unlock Developer options. Turn on USB debugging there, connect the phone with a cable, and tap Allow on the phone.
  • Your own iPhone: see 8d below.

8c. Run the app

Still in the mobile folder:

flutter pub get
flutter run --dart-define-from-file=.env

The first run takes 3–10 minutes; later runs are much faster. If several phones are connected, Flutter asks which one to use: type its number.

Or with a click: in VS Code open the Run and Debug panel (▶ icon on the left), choose Glamio (mobile) and press the green ▶. It already includes the .env file.

While the app runs Press r in the terminal to reload after a code change, or q to stop. After changing .env, stop and run again.

8d. On your own iPhone (Mac only)

  1. Connect the iPhone with a cable and tap Trust. On iOS 16 and newer also turn on Settings → Privacy & Security → Developer Mode (the phone restarts).
  2. Open mobile/ios/Runner.xcworkspace in Xcode (the .xcworkspace, not the .xcodeproj).
  3. Click Runner at the top of the left list → tab Signing & Capabilities → Team: add your Apple ID and choose it. If Xcode says the bundle identifier is taken, change it to something unique such as com.rosahair.app (better: rebrand the app id first, see Rebrand).
  4. Back in the terminal run flutter run --dart-define-from-file=.env and pick the iPhone. The very first iPhone build can take 30–60 minutes (Xcode builds Firebase once). It is not frozen; later builds take a minute or two.
  5. The first time, the iPhone may block the app: Settings → General → VPN & Device Management → your Apple ID → Trust.
Set up your salon · Step 9

Test it end to end

Do this once before you tell anyone about the app. Use a second email address for the "client" (a free Gmail is fine).

  • In the phone app, choose a service → a stylist (or "any") → a time → Book. It asks you to sign in: use the client email and the 6-digit code.
  • The booking shows under My bookings.
  • In the web admin, Calendar shows the same booking (the page updates by itself).
  • In the phone app, change the booking's time, then cancel it. The web admin follows both changes.
  • Sign out, then sign in with the owner email. You land on the schedule screen, not the client screens.
  • In the web admin, add a walk-in booking from Calendar → New booking.
Using Glamio

Daily use

Owner

Checks the dashboard and calendar, adds phone and walk-in bookings, moves or cancels bookings, marks the day's bookings Completed or No-show, manages services, stylists, hours and closures.

Stylist

Opens the phone app to see today's bookings (they update live), adds a walk-in client, marks Completed or No-show after the start time.

Client

Books, gets a confirmation and reminders (with push switched on), changes or cancels before the cut-off, calls the salon after it.

A booking's life

Every booking is in one of four states:

StateMeansWho sets it
ConfirmedBooked and coming. Every new booking starts here.Automatic
CompletedThe client came. Only completed bookings count as revenue.Owner or stylist, after the start time
No-showThe client didn't come. The time becomes free again.Owner or stylist, after the start time
CancelledCalled off by the client (before the cut-off) or the salon. Final.Client, owner or stylist

Completed and No-show have an Undo button for mistakes.

Mark every past booking Glamio never guesses whether a client came. Bookings stay "Confirmed" until someone marks them, and the dashboard shows "N past bookings have no outcome yet" with a link. Mark them, and the revenue and no-show numbers stay right.

Staff app access

A stylist on the Stylists page is just a record (name, hours, services). To let that person open their own schedule in the phone app, give them access:

  1. Web admin → Stylists → the person → App access. Type their email and click Give access.
  2. They install the app and sign in with that email. They now see their schedule instead of the client screens. The admin shows Joined (or Invited while they haven't signed in yet).
  • Someone leaves: click Remove access. They become a normal client again: they can still book, but no longer see the salon's schedule or clients. Their past bookings stay.
  • Short break (holiday, sick leave): switch the stylist's Active off. They disappear for new bookings, and the app shows them "Your schedule is paused" until you switch it back on.
  • Wrong email? Each stylist has one invite: click Remove access, then give access with the right email.

Push notifications

With push on, clients get "Booking confirmed", a reminder 24 hours before and another 1 hour before; stylists and the owner get "New booking", "Booking moved" and "Booking cancelled". Glamio works fine without push: everything else stays the same.

You'll need A Google account (Firebase), and for iPhones an Apple Developer account. Do the app id change first.

1. Create a Firebase project and connect the app

  1. At console.firebase.google.com click Create a project (Google Analytics is not needed).
  2. Install the Firebase tools and sign in: 
    npm install -g firebase-tools
firebase login
dart pub global activate flutterfire_cli
  3. In the mobile folder, connect the app to your project. Pick your project and tick android and ios: 
    flutterfire configure --out=lib/core/push/firebase_options.dart
    This creates the Firebase files for both platforms. The Android build picks them up by itself.

2. iPhone only: Apple's push key

  1. In Apple Developer → Keys create a key with Apple Push Notifications service (APNs), download the .p8 file, and note the Key ID and your Team ID.
  2. Firebase → Project settings → Cloud Messaging → your iOS app → APNs Authentication Key → Upload.
  3. In Xcode (mobile/ios/Runner.xcworkspace) → Runner → Signing & Capabilities → + Capability: add Push Notifications, and Background Modes with Remote notifications ticked.

3. Give the server function its keys

  1. Firebase → Project settings → Service accounts → Generate new private key. A .json file downloads. Keep it private.
  2. Supabase dashboard → Edge Functions → Secrets. Add two secrets:
    FCM_SERVICE_ACCOUNTOpen the .json file in VS Code, select everything, and paste it as the value.
    CRON_SECRETA long random text you make up, for example 40 letters and numbers. Keep it in your notes.

4. Start the sender

The server checks for new messages every minute. Start it once: in Supabase SQL Editor, paste the following, replace the two values in capitals, and click Run:

select vault.create_secret('https://YOUR-PROJECT-REF.supabase.co', 'project_url');
select vault.create_secret('THE-SAME-CRON-SECRET', 'cron_secret');

select cron.schedule('glamio-send-push', '* * * * *', $$
  select net.http_post(
    url := (select decrypted_secret from vault.decrypted_secrets where name = 'project_url')
           || '/functions/v1/send-notifications',
    headers := jsonb_build_object(
      'Content-Type', 'application/json',
      'x-cron-secret', (select decrypted_secret from vault.decrypted_secrets where name = 'cron_secret')),
    body := '{}'::jsonb
  );
$$);

5. Switch it on in the app

In mobile/.env set PUSH_ENABLED=true, then run the app again. It asks for permission to send notifications: tap Allow.

Test: sign in as a stylist on one phone, book as a client on another phone (or the emulator). The stylist's phone shows "New booking"; tapping it opens the booking.

Messages are never sent twice or late If a message can't be delivered within 2 hours, or the booking was cancelled meanwhile, Glamio drops it instead of sending old news.

Publish on Google Play

Before you start Finish the rebrand (at least the app id, name, icon and privacy policy link).

1. Make your upload key (once)

Google needs to know updates really come from you, so every upload is signed with your private upload key. Create it (it asks for a password and some details):

keytool -genkey -v -keystore ~/upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
keytool -genkey -v -keystore $env:USERPROFILE\upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload

If keytool is not found, use the one inside Android Studio: "C:\Program Files\Android\Android Studio\jbr\bin\keytool".

Then create the file mobile/android/key.properties with your values:

mobile/android/key.properties
storePassword=THE-PASSWORD-YOU-CHOSE
keyPassword=THE-PASSWORD-YOU-CHOSE
keyAlias=upload
storeFile=/Users/you/upload-keystore.jks

On Windows write the path with double backslashes: storeFile=C:\\Users\\you\\upload-keystore.jks. Glamio uses this file automatically for release builds.

Back up the key file and passwords Keep upload-keystore.jks and its password somewhere safe (not in the project folder, never on GitHub). They are already excluded from Git.

2. Build the app file

Each upload needs a higher version number. In mobile/pubspec.yaml, version: 1.0.0+1 means "version 1.0.0, build 1": raise the number after + for every upload. Then, in mobile:

flutter build appbundle --dart-define-from-file=.env

The file to upload is mobile/build/app/outputs/bundle/release/app-release.aab.

3. Create the app in Play Console

  1. Play Console → Create app: name, language, App, Free.
  2. Complete the Set up your app tasks. Two need Glamio-specific answers:
    • Privacy policy: your policy link.
    • Data safety → Data deletion: people can delete their account in the app (Profile → Delete account) and on the web at YOUR-WEB-ADMIN-ADDRESS/delete-account. Give that web link.
    • App access: booking needs sign-in with an emailed code. Explain this, and give the reviewers a test email inbox they can use, or ask us about a demo login.
  3. Upload the .aab to Testing → Internal testing first, try it on your phone, then promote it to Production.

Google's review usually takes a few days for a new app. New personal developer accounts must first run a closed test with a group of testers before they can publish; Play Console tells you if this applies to you.

Troubleshooting

Every screen says "permission denied for table …"

The project was created with Automatically expose new tables unticked (Step 1). The safe fix is a new Supabase project with that box ticked, then Steps 2–5 again (about 15 minutes). Don't try to fix it by granting access by hand: Glamio deliberately limits which columns people can change (for example, nobody can change their own role), and a broad grant would remove that protection.

The app shows "Setup needed — Missing keys"

mobile/.env is missing or incomplete, or the app was started without it. Check the three required lines, and start with flutter run --dart-define-from-file=.env from inside the mobile folder.

No sign-in email arrives

  • Look in the spam folder.
  • Check that your domain is Verified in Resend, and the SMTP settings in Supabase (Step 3b). Resend's Emails page shows each email it sent, or why it failed.

The email has a link instead of a 6-digit code

The code design wasn't sent. Run Step 3c (supabase config push) again, after custom SMTP is switched on.

The web admin says "Owners only"

You signed in with a different email than the one in setup.sql. Either sign in with that email, or make your current email the owner: in Supabase SQL Editor run the following (with your email), then sign out and in again:

insert into public.invites (business_id, email, role)
values ('00000000-0000-0000-0000-00000000b001', 'your-email@example.com', 'owner');

The app shows no free times

Check in the web admin, in this order: the stylist has working hours on that weekday; the stylist is ticked for that service; both the stylist and the service are Active; there is no closure or time off that day; the day is within Book up to; for today, Minimum notice may have pushed all times past closing time.

Times look shifted by an hour or more

The business time zone is wrong. Fix it in web admin → Settings. The app always shows times in the salon's time zone, wherever the client is.

"supabase: command not found" (Windows: "not recognized")

On Windows, use npx supabase. On Mac, run brew install supabase/tap/supabase again, then open a new terminal.

supabase link or db push fails with a password error

Reset the database password in Supabase → Project Settings → Database, then run the command again with the new one.

The app worked yesterday, today nothing loads

On the free Supabase plan, projects pause after a week without use. Open the dashboard and click Restore. For a real salon, use the Pro plan.

The Android build fails

  • Run flutter doctor and fix anything marked ✗ for Android.
  • Then clean and try again, in mobile: flutter clean, then flutter pub get, then run again.

The iPhone build fails with "Signing" or "No team"

Set your Team in Xcode (Step 8d). With CocoaPods errors, run in mobile/ios: pod repo update and then pod install.

Push notifications don't arrive

  • PUSH_ENABLED=true in .env, the app was restarted, and you tapped Allow.
  • You don't get a push about your own action (book as a client, check the stylist's phone).
  • In Supabase SQL Editor, this shows the last messages and any error (push_not_configured means the Firebase secret is missing): 
    select kind, created_at, sent_at, attempts, last_error
from public.notification_outbox order by id desc limit 10;

Glossary (plain words)

App id / package name / bundle idThe app's unique name in the stores, like com.rosahair.app. Android and Apple use different words for the same thing.
BuildTurning the code into an app file you can install or upload.
CLI"Command-line interface": a program you use by typing commands in the terminal.
DatabaseWhere all the data lives: bookings, clients, services. Like a set of very organised spreadsheets.
DeployTo put something online so others can use it.
DNS recordsSettings of your domain name that tell the internet who may send email for it, among other things.
Edge FunctionA small program that runs on Supabase's servers, not on the phone.
Emulator / simulatorA pretend phone on your computer, for testing.
.env fileA small text file with the app's settings and keys. Private: never share or upload it.
Key (API key)A long code that lets a program talk to a service. "Publishable" keys may sit in an app; "secret" keys must stay private.
MigrationA file that creates or changes database tables. Glamio's are in supabase/migrations/.
Push notificationA message that pops up on the phone, even when the app is closed.
Repository (repo)A project folder whose history Git keeps, here stored privately on GitHub.
SDK"Software development kit": the building blocks a tool needs, like the Android SDK.
SMTPThe standard way programs send email. Resend gives you an SMTP "post office" for your domain.
SQL / SQL EditorSQL is the language for talking to a database. The SQL Editor is the box in Supabase where you paste and run it.
SupabaseThe online service that hosts Glamio's database, sign-in and server functions.
TerminalA window where you type commands. See The terminal, in 3 minutes.
Time zone nameThe official name of a time zone, like Europe/London. It knows about summer and winter time.
Walk-inA client who comes in without a booking; staff add them in the app so the time is blocked.
